## 1. 目标与日常流程

项目探索：考虑人类执行成本后，计算机是否偏好某些魔方中间目标，并形成可解释的分阶段还原策略。

记录必须说明：做了什么、为什么这样做、证据支持什么。另设学习日志，记录你亲自理解与完成的内容。

1. 实验前写问题、假设、对照、指标和停止条件。
2. 每次运行保留配置、实际打乱、原始结果、代码版本和环境。
3. 每次研究结束用约 5 分钟写研究日志，再用几句话补学习日志。
4. 每周用约 15 分钟总结，完成里程碑后更新 README。

所有示例、待填写参数和预计规模均不代表实际结果。未运行标为“计划中”，失败实验也保留。

## 3. 编号与状态

- Experiment ID：EXP-001 起顺序编号，一项对应一个研究问题及预先约定的比较。
- Run ID：EXP-001_20261008T150000+0800_001 为格式示例；每次唯一，重跑不覆盖旧目录。
- Session ID：2026-10-08-S01；同日多次活动在日志下分节。
- Decision ID：DEC-001 起顺序编号。
- 状态：计划中 → 运行中 → 待分析 → 已完成；中止时写原因。

同一实验可以多次运行。调参用新 Run ID；研究问题或主要评价方法改变时建新实验，关联旧实验。

## 4. 一项实验的工作流程

### 运行前

1. 写出具体问题，以及支持或削弱假设的结果。
2. 确定变量、主要指标、搜索预算、失败处理和停止规则。
3. 区分开发、筛选、最终测试数据；最终测试集不参与调参。
4. 提交设计、配置和待运行代码，记录完整 commit SHA。
5. 做小规模冒烟运行，估计耗时、核对字段；冒烟数据独立标记。

### 运行中

每次建立独立目录，保存成功、失败、超时和异常。发现错误后保留原结果，标为无效并说明原因；修复、提交后创建新运行。

### 运行后

1. 你先独立写观察和解释，再请 AI 检查遗漏、反例和混杂因素。
2. 先检查成功率、超时率及异常，再比较步数、预测成本与计算开销。
3. 相同打乱做配对比较，保留逐样本差异，报告样本数与不确定性。
4. 区分观测、解释与未验证猜想，不支持假设时照实写。
5. 更新状态，关联全部 Run ID，提交报告和小型结果。

看到结果后新增分析标为“探索性分析”，后续使用独立样本验证。

## 6. 每次运行的证据包

~~~text
results/runs/<run_id>/
  config.json        # 实际参数
  metadata.json      # 版本、环境、时间、状态
  scrambles.jsonl    # 实际打乱和样本 ID，或精确数据集引用
  samples.csv        # 逐样本结果，包含失败
  summary.json       # 从原始结果生成的汇总
  stdout.log         # 输出、异常、中断
  figures/           # 需要时生成
~~~

第一阶段可以手工保存，后续再开发运行器；此处不是已有软件功能。

### metadata.json 字段

| 字段 | 用途 |
|---|---|
| experiment_id, run_id | 实验与运行身份 |
| started_at, ended_at, timezone | 带时区时间，统一 Asia/Shanghai |
| status, error | completed / interrupted / failed，异常原因 |
| git_commit, git_dirty | 完整 SHA、有无未提交变更 |
| command, config_sha256 | 实际命令及配置校验值 |
| seed, rng, rng_version | 随机种子、生成器、相关版本 |
| dataset_id, dataset_sha256 | 精确定位打乱 |
| python_version, dependencies | Python 和实际依赖版本 |
| os, cpu, gpu, threads | 性能比较所需环境 |
| action_set, metric, cost_model_version | 动作、计数口径、成本模型 |
| search_algorithm, budget | 方法、节点 / 时间 / 内存上限 |

正式比较使用干净提交。git_dirty=true 时保存补丁及新增源文件，否则标为探索运行，正式结论在固定版本上复跑。运行 commit 指运行代码版本，不是后来提交报告的版本。

### samples.csv

~~~csv
run_id,sample_id,goal_id,status,solution,move_count,predicted_cost,cost_unit,search_seconds,nodes_expanded,error
~~~

status 区分 success、timeout、error、no_solution_within_bound。预算内未找到解不代表数学上无解。失败样本的步数和成本留空，不写 0。

打乱和解用统一转动记号。尚未测预测成本时留空；未校准模型单位写 arbitrary_units，不能写成秒。

汇总报告总样本数、成功数、超时数、异常数。仅成功样本统计的指标标为“成功样本均值”。不同组成功率不同时，不能直接用该均值判优；事前约定失败惩罚或共同成功样本分析，并单独报告失败。

随机种子不足以完全复现，还须保留实际打乱、生成方式、配置和版本。时间预算受硬件影响，节点预算便于比较资源，同时报告实际耗时。

## 9. 魔方项目的实验边界

1. **打乱分布**：固定长度随机转动不是均匀随机状态。记录生成方式、长度、相邻动作限制；结论只覆盖测试分布。
2. **转动口径**：明确 HTM / QTM 等计数。扩展 M、宽转、整体转体前，明确中心 / 参考坐标系及合法性；不能套用仅外层转动时的全部编码约束。
3. **目标约束**：记录块、位置、朝向约束。固定块不能完整表达 EO 等阶段目标。比较时控制约束强度或披露差异。
4. **结构保持**：每步保持，还是阶段结束时恢复？两种要求的搜索空间不同。
5. **搜索偏差**：第一阶段便宜不等于整体便宜；需评估后续完成成本。启发式含已有方法知识时披露。
6. **人类成本**：人工权重只是代理。未实测校准的成本下降不能写成实际秒数；识别、记忆、观察、转动分别报告。
7. **真人测试**：保留熟练程度、训练时长、器材、打乱顺序、计时方式、停顿、DNF、原始成绩。一人的短期结果只支持个人可行性。
8. **发现声明**：预先限定相连块会影响结果。是否重新发现、是否全新，需查文献并说明搜索先验。
9. **测试隔离**：筛选、调参、最终测试分开，不挑选最好看的测试批次。

## 10. 第一项实验：EXP-001

**三阶魔方模拟器正确性验证。状态：计划中。**

这是工程验证，暂不验证人类成本偏好块结构的研究假设。

运行前明确：

- CP/CO/EP/EO 下标表示位置还是块身份。
- 角、棱编号及朝向定义，保存示意或文字表。
- 第一版仅 18 个外层面转，M 层与整体转体后续单独验证。
- 本人先推导一个面转映射，AI 审查后再实现其余动作。

| 检查 | 预期 | 验证范围 |
|---|---|---|
| 初始状态 | 还原、排列完整、朝向有效 | 初始化 |
| 面转四次 | 对合法状态恢复 | 循环一致性 |
| 动作与逆动作 | 恢复原状态 | 逆运算 |
| 双转 | 等于两次同面四分之一转 | U2 等实现 |
| 已知单步状态 | 符合独立手工推导 | 方向与映射 |
| 外层转动合法性 | 朝向总和、角棱排列奇偶关系符合约定 | 非法更新 |
| 目标判断 | 位置和朝向正确为真，错误为假 | is_goal 语义 |
| 打乱后逆序 | 恢复原状态 | 组合动作 |

逐项验证后，计划用固定种子生成 1,000 条长度为 25 的随机转动序列做回归检查；按速度调整并记原因。它不是均匀随机状态数据集。

逆序复原与四次复原可能让互相一致的错误实现通过。必须加入独立推导的已知状态；需要时用独立可信实现交叉核对，记录来源与版本。

完成条件：

- EXP-001 报告保留设计、命令、结果、局限。
- 固定版本的模拟器、测试与输出。
- 本人状态表示说明、一个独立面转推导。
- 约定检查通过，修复过程保留，未验证范围明确。

随后开始短打乱和小目标的 BFS，不直接搜索任意三阶完整状态空间。

## 11. 版本、备份与展示

形成可解释的改动后提交，说明目的，例如 docs: define EXP-001 correctness checks。日志关联 commit。

代码、配置、文档、小型基准和小型原始结果进入 Git。缓存、虚拟环境、临时文件不入库。大型结果、视频、模型另存，仓库记录稳定位置、大小、SHA-256、恢复步骤；不能只留在个人电脑。推送远端后才完成远端备份。

验证过的提交用标签固定里程碑，附功能、验证、限制、复现命令：

- M1：模拟器正确性。
- M2：小目标搜索与可复现记录。
- M3：步数成本与人类代理成本配对比较。
- M4：中间目标筛选及独立测试。
- M5：报告与展示。

每个里程碑保留关键图表或演示、失败案例、本人贡献说明、复现路径。没有结果不写成绩。公开前清理凭据和无关个人信息。

最终 README 能追溯：问题 → 方法 → 实验设计 → 原始数据 → 分析 → 局限 → 本人贡献。图表和 PPT 在证据形成后制作。
